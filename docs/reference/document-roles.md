# 문서 역할 구분 가이드

목적: 새 프로젝트에서 `reference`, `strategy`, `prd`, `product`, `research`, `decisions` 역할을 헷갈리지 않도록 기준을 정한다.

## 한눈에 보는 구분

- `reference`: 계속 참고하는 기준 문서
- `strategy`: 서비스 방향과 판단 기준 문서
- `prd`: 무엇을 왜 만들지 정의하는 요구사항 문서
- `product`: 실제로 어떻게 만들지 정의하는 설계/실행 문서
- `research`: 근거 자료와 검증 결과
- `decisions`: 왜 그렇게 결정했는지 남기는 기록

## reference

질문:
- 계속 참고해야 하는 상수는 무엇인가
- 제품보다 앞서는 기준은 무엇인가

예:
- 브랜드 가이드
- 도메인 용어 정의
- 운영 규칙
- 법적 유의사항

## strategy

질문:
- 어떤 방향으로 갈 것인가
- 무엇을 우선할 것인가

예:
- 서비스 전략
- 포지셔닝
- 로드맵
- 성공 지표

## prd

질문:
- 왜 이걸 만드나
- 누구를 위한 건가
- 어떤 요구사항이 필요한가

예:
- 문제 정의
- 목표
- 범위 / 비범위
- 성공 기준

## product

질문:
- 화면은 어떻게 구성하나
- 데이터 구조는 어떻게 잡나
- 어떤 순서로 구현하나

예:
- 기능 스펙
- 사용자 흐름
- IA
- 구현 계획

## research

질문:
- 어떤 근거가 있는가
- 어떤 실험 결과가 있는가

예:
- 인터뷰 요약
- 경쟁사 분석
- 실험 로그

## decisions

질문:
- 왜 이렇게 결정했는가
- 어떤 대안을 버렸는가

예:
- ADR
- 주요 구조 결정 메모

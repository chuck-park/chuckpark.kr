# harness engineering guide

목적: 이 스캐폴드가 단순 문서 보일러플레이트를 넘어서, 에이전트 실행 환경을 어떻게 구조화하려는지 설명한다.

핵심 축
- `docs/`: 기준, 전략, PRD, 제품 설계
- `evals/`: 반복 가능한 평가 작업과 스코어카드
- `policies/`: 권한, 네트워크, 시크릿, 승인 정책
- `standards/`: 구조 invariant, 실패 분류, 품질 기준
- `runs/`, `artifacts/`: 실행 결과와 산출물
- `scripts/`: 구조 검증과 평가 실행 자동화

운영 원칙
- 모델 품질만 믿지 않고 평가와 정책을 함께 관리한다.
- 새 기능보다 먼저 실패 유형과 권한 경계를 정리한다.
- 실행 중 생성되는 로그와 산출물은 문서와 분리해 저장한다.
- 사람이 읽는 기준 문서와 자동화가 읽는 구조 규칙을 동시에 유지한다.
